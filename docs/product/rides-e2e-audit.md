## Найденные и исправленные дефекты

1. **Нативные E2E на `main` были красными** (`Rides category did not open`): после появления хаба Rides, нового экрана заказа и экрана оценки сценарии не обновили, а workflow запускался только при правке своих файлов. Сценарии обновлены; workflow теперь запускается и при изменениях Rides, Executor, Maps, миграций и backend Rides.
2. **Плитки хаба Rides сливались в один a11y-узел** (TalkBack и UI-автоматизация видели один элемент на пять категорий) — `Semantics(container: true)` на плитку.
3. **`RideRatingSummaryIntegrationTest` считал все оценки в таблице** — хрупкий к порядку тестов; счёт ограничен своей поездкой.
4. Сбой E2E не оставлял диагностики — теперь сохраняются скриншот и дерево UI.

## Добавленные проверки

- `RideLifecycleHttpIntegrationTest` (PostgreSQL, реальный HTTP-слой, без test-transaction): полный путь котировка → заказ → поиск → оффер → принятие → подача → поездка → завершение → оценка; идемпотентный повтор; второй заказ при активном; чужие поездки/GPS/оценки; недопустимые переходы; валидация координат; лимит GPS 3 с; водитель не одобрен; отказ водителя и `NO_DRIVER_AVAILABLE`; опоздавшее принятие; отмена при поиске; гонка при принятии (один держатель оффера, остальные 404; второй живой оффер на поездку невозможен — частичный уникальный индекс); offline и устаревший GPS; RBAC Admin.
- Нативные сценарии дополнены оценкой из UI с проверкой в backend, временем стадий и диагностикой падения.

## Пробелы (не объявляются реализованными)

- Нет фонового планировщика диспетчеризации: следующий оффер и истечение поиска происходят только при вызове `POST /rides/{id}/dispatch` клиентом.
- Live Tracking — polling, не WebSocket/SSE. Executor отправляет GPS только на переднем плане (нет foreground service), в фоне позиция устаревает за 2 минуты. ETA в отслеживании не подтверждён.
- Admin: список поездок — последние 100 без поиска, фильтров и пагинации; нет API истории событий поездки и действий над проблемной поездкой (принудительная отмена); Admin Android UI в этом аудите не прогонялся.
- Не покрыто нативными тестами: GPS выключен, отказ в разрешении геолокации, нет интернета на экранах карты, перезапуск приложения во время поездки, истёкший токен в UI, сворачивание приложения, утечки и ANR. Часть покрыта Flutter-тестами или API-тестами, но не на устройстве.
- Конкурентное принятие двумя водителями проверено на API/БД, не на двух устройствах.
- Итоговая сумма на экране завершения показывается как «460.0 KZT» (формат) — косметика.
- Производительность измерена только на эмуляторе CI; значения не переносятся на устройства.

Публичный запуск Taxi не включался; управление остаётся через backend feature flags.
