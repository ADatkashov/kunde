## Integrity notes

- Each requirement ID appears once in document 05 and once in this matrix; IDs from the story list are distinct prefixes where appropriate.
- Every requirement has an AC link. AC-01 through AC-34 each link to a story; category rows reuse the relevant category-level story/AC rather than implying unsupported UI behavior.
- Every transactional requirement maps to the lifecycle, error and integration contracts that govern recovery.
- A requirement is not “done” until implementation/test artifacts later reference its ID and its launch dependency is satisfied.
