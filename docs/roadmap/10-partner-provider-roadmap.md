# 10 — Partner & Provider Roadmap

## Partner

Minimum pilot sequence: invite/application → identity/business verification → agreement and category/branch approval → profile/catalog import or entry → availability/service area → test order → work queue accept/reject/status → support and reconciliation guidance. Start with only the controls the cohort needs; add staff roles, richer analytics and payouts after operating policies are approved. Partner changes to price/availability are audited and reflected before customer commitment.

## Provider (conditional)

D-02 decides whether a separate provider platform exists. If merchant pickup/merchant delivery is sufficient, do not build provider app. If a separately contracted provider pool is required, establish role verification/documents, availability, request acceptance, task state, location/navigation permissions, earnings/payout visibility and support before dispatch. Location access is purpose-limited and disclosed; no provider payout claim until finance flow is approved.

## Shared and distinct capabilities

Both roles need identity, scoped permissions, onboarding status, notifications, task/order context and support. Partners manage business, branches, catalog and customer commitments; providers execute assigned fulfillment and see only the minimum order/contact/location data. Separate role grants and retention policy. Web versus mobile is a product/operations choice; use the lightest interface that supports reliable pilot operations.
