# 22 — Delivery Risks & Blockers

The structured risk register and owners/mitigations are in [`backlog/risks.yaml`](backlog/risks.yaml). The following are real launch gates, not hypothetical engineering tickets.

| Risk / blocker | Severity | Resolution evidence |
|---|---|---|
| D-01 category/market approved 2026-11-13; cohort/zone/operational proof undecided | Critical; blocks MVP scope | Signed category and operational proof checklist |
| D-02 fulfillment responsibility undecided | Critical; blocks partner/provider design | Contracted model, status ownership, exception and liability flow |
| D-03/D-04 payment, funds flow, fees/tax/settlement undecided | Critical; blocks real transaction | Provider capability, legal-approved funds flow, signed terms, reconciliation plan |
| D-06 cancellation/refund rules undecided | Critical; blocks customer commitment | Published category policy and exercised refund/dispute procedure |
| D-07/D-08 identity, residency, retention, AI processor open | High/Critical; blocks production PII | Counsel/security/privacy approval and implemented controls |
| No selected OTP/maps/messaging/hosting provider | High; integration and cost uncertainty | Procurement review, sandbox and fallback proven |
| Supply/support/operations capacity unproven | Critical; blocks public pilot | Verified cohort, staffed rota, runbooks, rehearsals |
| Admin separation/refund limits D-14 open | High; blocks operator money actions | Approved RBAC/dual control and negative tests |
| Team capacity/ownership unknown | High; delivery confidence unknown | Named owners, availability and cycle-time baseline |
| Scope expansion across categories/AI | High; schedule/quality dilution | Feature flags and evidence-based stage gates |

Mitigate through decision owners and dates, contract tests, adapter boundaries, operational rehearsals, staged rollout and category/zone kill switches. Owner names are intentionally unassigned until the organization assigns them; every open blocker needs one before Foundation exit.
