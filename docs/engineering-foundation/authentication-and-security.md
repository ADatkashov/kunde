# Authentication & Security

The app does not issue tokens and does not offer registration or login. Backend can validate bearer JWTs from an externally approved OIDC issuer through `OIDC_ISSUER_URI`; `OIDC_AUDIENCE` is mandatory with the issuer. Nimbus validates signatures from discovered JWKs, standard issuer/time validation is enabled, and an audience validator is composed. Missing audience fails startup. It does not exchange credentials, refresh tokens or manage user sessions. Without an issuer, protected APIs fail closed. Configuring a real issuer is blocked by ADR-009, D-05 and D-07 review. Audience acceptance/rejection and no-issuer fail-closed behavior are tested; live discovery, keys, and signed provider tokens are not verified.

Implemented: stateless security boundary, deny-by-default, safe API errors, constrained CORS, request-ID validation and non-disclosing exception handling. Public routes are health, capability metadata, the non-sensitive OpenAPI document and empty read-only catalog/search. Actuator exposes only health with hidden details; `info` is not exposed. No password, OTP or token is stored/logged. No rate limiter was added because no public identity or mutation route exists; abuse controls are required before adding either.

Before production complete real-issuer/token verification, role/scope mapping and resource-level authorization, staff MFA, abuse limits, managed secret rotation, TLS termination, dependency scanning, privacy/residency approval, security tests and incident procedures. No dependency vulnerability scan was run because scanner tooling was unavailable. This is not a compliance certification.
