# Identity provider comparison

**Snapshot date:** 2026-11-10. Product capabilities and prices change; treat all plan and version boundaries as launch-time verification items. “Native” below means documented platform capability, not a claim that the exact KUNDE flow is already configured.

## Cross-cutting findings

- OIDC alone does not imply SMS OTP, phone-first UX, passwordless enrollment, passkeys, log export or Kazakhstan data residency.
- All candidates require explicit `issuer`, audience/resource and client configuration; KUNDE's existing Spring decoder is useful only after provider metadata and token claims are verified.
- No candidate has been provisioned or connected. SLA, regional data copies, exact OTP carrier behavior, export completeness, contractual subprocessors and admin audit retention are **vendor confirmation required**.
- Keep business authorization in KUNDE. IdP groups can be coarse hints but cannot replace tenant/resource authorization.
