# Operational follow-up tasks

| Owner to assign | Action | Acceptance evidence |
|---|---|---|
| Platform and database | Provision dedicated Keycloak PostgreSQL with least privilege, encrypted DB connections, supported versions and monitored resource limits | Record the topology, grants, TLS verification and maintenance plan. Exercise a DB restart with synthetic sessions. |
| Platform and security | Design encrypted backups and secret storage for DB credentials, bootstrap/admin recovery and signing material. Separate backup and restore permissions. | Restore in an isolated environment. Compare realm, user and key metadata and prove sign-in. Record RPO, RTO and deletion. [Keycloak export limits](https://www.keycloak.org/server/importExport) |
| Platform | Design redundant Keycloak nodes, PostgreSQL failover, proxy/TLS and private admin and management access | Test correct host/forwarded headers and exact discovery issuer. Drain or lose one node and verify login, refresh and JWKS. Test network failure and stale DNS. [Production guide](https://www.keycloak.org/server/configuration-production), [reverse proxy](https://www.keycloak.org/server/reverseproxy), [HA guide](https://www.keycloak.org/high-availability/introduction) |
| Operations | Set login/refresh/error/latency, database and cache alerts. Retain useful Keycloak admin and user events and Spring authorization outcomes. | Test alerts and admin audit trail. Verify redaction for bearer values, codes, OTP and contact details across application, proxy, trace and export. [Keycloak metrics](https://www.keycloak.org/observability/configuration-metrics) |
| Operations and QA | Rehearse one supported upgrade, rollback and key rotation. Measure at representative login and refresh rates. | Publish version and advisory checks, DB restore order, readiness canaries and measured capacity. [Keycloak upgrades](https://www.keycloak.org/docs/26.8.2/upgrading/) |
| Identity and product | Rehearse migration and exit with verified `(issuer, subject)` mapping, duplicate identities, password/MFA limitations and user communications | Demonstrate stable KUNDE IDs and an approved remediation plan for credentials that cannot move. |
| Privacy/legal and procurement | Inventory all copies and processing locations, evaluate Kazakhstan storage and transfer obligations, and obtain vendor, support and retention terms | Record written counsel review and signed commercial evidence. [Kazakhstan personal-data law](https://adilet.zan.kz/rus/docs/Z1300000094) |
| Product, security and OTP integration | Prototype the IdP-owned challenge and replaceable delivery adapter with an approved sandbox when authorized | Test expiry, one-time consumption, throttling, spend caps, retries and delivery receipts. IdP verifies challenge proof. Spring transport status supplies no authentication. [OTP boundary](../otp-delivery-architecture.md) |
